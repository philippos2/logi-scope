# デモ動画の台本案

3〜5分の編集済み動画を想定する。ローカルLLMの実際の待ち時間によって録画時間は長くなる。待ち時間を短縮した箇所は「待機部分を短縮」と明示し、実際より高速に動くとは説明しない。

## 撮影前

[実行ガイド](getting-started.md)でAgent APIとReactを起動する。配送更新サービスと専用荷物も準備する。APIを最新コードで起動し、画面を再読み込みする。秘密情報や個人の通知が映らないよう、ブラウザのデモ画面を中心に録画する。撮影・編集は利用者が行う。

| 目安 | 操作 | 説明例 |
|---|---|---|
| 0:00〜0:20 | 初期画面を表示 | 「LogiScopeは、架空の物流データを使い、業務DBと文書を横断調査するAIエージェントのデモです。」 |
| 0:20〜1:40 | 多段調査のサンプルを選び、調査する。回答・履歴・根拠を展開 | 「検索順序は画面では指定しません。LLMがToolを選び、取得した顧客・荷物・障害の情報を次の検索に利用します。」 |
| 1:40〜2:20 | 曖昧性のサンプルを調査 | 「同名顧客が複数いる場合は勝手に選ばず、営業所などの追加情報を求めます。」 |
| 2:20〜3:40 | 更新用荷物を調査し、配送報告欄から配達完了を報告。「更新用荷物を調べる」→「調査する」 | 「配送報告はAgentとは別の更新APIが受け付けます。Agentは読み取り専用のまま、再調査で更新後のDBを確認します。」 |
| 3:40〜4:00 | 配達完了の回答と根拠を表示 | 「ローカルLLM、PostgreSQL、pgvector、Reactで再現できます。本番用の認証や外部配送システムとの連携は対象外です。」 |

多段調査では、単に履歴の件数だけでなく、前段のIDが後段の引数へ利用されている箇所を見せる。モデル内部推論を表示・説明する必要はない。回答に未確定事項があれば、その表示も残す。

## 撮影後

対象コミットとモデル、編集で短縮した待機部分を動画の説明へ記載する。想定外の結果が出た場合は原因を確認してから撮り直す。成功した録画だけで、任意の質問への品質を保証する表現は使わない。
