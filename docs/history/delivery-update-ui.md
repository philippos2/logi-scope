# 配送状況の報告画面の検証

2026年10月6日、main `ca9b642` の配送イベント更新APIを、既存のReact画面から利用できるようにした。

## 実装

- 更新対象は専用荷物 `SHP-UPDATE-001` に限定し、状態と報告日時を入力する。
- 画面用プロキシから更新専用APIへ接続する。Agentの読み取り専用接続と資格情報の分離は維持する。
- 通信失敗・時間超過などで登録結果が不明な場合、同じイベントキー・状態・日時を保持して再送する。自動再送は行わない。
- 報告と調査の同時送信を防止し、更新後の再調査は利用者が明示的に行う。以前の回答を最新状態として扱わない。

再送用の情報は画面のメモリにのみ保持する。結果が不明なまま再読み込みした場合は、登録状態を調べてから新しい報告を行う。この制限と初期化手順は[配送イベント更新デモ](../delivery-updates.md)に記載した。

## 検証結果

- フロントエンドの自動テスト：17件中17件成功。二重送信、同じ内容の再送、拒否後の編集、タイムアウト後の遅延応答、調査との同時送信防止を確認した。
- ESLint・型確認・本番用ビルド：成功。
- 実際の画面用プロキシ経由の確認：3件中3件成功。更新前のAgent回答、更新と同じイベントの再送、更新後のAgent回答を確認した。前後の調査には実ローカルLLMを使用した。

プロキシの確認はHTTP経由で行い、確認後、更新用荷物を初期状態の輸送中へ戻した。その後、利用者がブラウザで配達完了を報告し、Agentの再調査で回答が配送中から配達完了へ変わることを確認した。ブラウザで全異常系を手動確認したわけではない。

バックエンド、採用モデル、依存ライブラリはこの作業では変更していない。
