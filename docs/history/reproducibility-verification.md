# 別環境での再現性確認

検証日: 2026-10-06。対象コードはmainの`b1e6b04`。

## 方法

Git管理対象のファイルだけを別ディレクトリへ展開し、開発用とは別のComposeプロジェクトを作成した。DBと埋め込みキャッシュは空のnamed volumeから開始し、資格情報も新規生成した。開発用APIと競合しないようホストポートのみ18000へ変更した。

ホストのDocker Engine・Ollama・取得済みQwenモデルは再利用した。Dockerの既存ベースレイヤーも利用しており、OSの初期導入やQwenの再ダウンロードを含む完全な新規PC検証ではない。別OSや最小スペックの検証でもない。

[実行ガイド](../getting-started.md)と同じ順序でコンテナのビルド、マイグレーション、架空seed、実E5によるingest、API起動、実LLMデモ、自動テスト、マイグレーション整合性確認を行った。モデルの初回取得を含め、10チャンクを正本6件から生成できた。開発用DB・キャッシュには接続していない。

## 結果

- 実LLMのA〜E: **5件中5件成功**。
- 全自動テスト: **141件中141件成功**（失敗・スキップ0件）。
- `alembic check`: 追加差分なし。
- ホストから別ポートの`GET /health`: 成功。
- 検証後は専用コンテナ・DB・埋め込みキャッシュを削除。

公開応答はGit対象外の`artifacts/fresh-setup-verification.json`へ保存した。生LLM応答・内部推論・資格情報は保存していない。
