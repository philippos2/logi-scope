# 配送状態による一覧検索と架空データの拡充

2026年10月6日、個別の荷物照会に加えて、配送状態による一覧・有無を調査できるようにした。

## 変更

従来の`search_shipments`は顧客IDまたは荷物IDが必須で、「行方不明の荷物って今ある？」にも対象指定を求めていた。`status`単独の検索を追加し、複数条件はAND、取得上限と省略表示を維持する。Toolの選択はLLMが行い、自然言語の質問を固定フローへ振り分ける処理は追加していない。

所在不明として登録された`missing`を既存の3状態へ追加した。遅延から所在不明を推測しない。DB制約はAlembicで更新し、missingレコードが残ったままのダウングレードはデータを変換・削除せず拒否する。

業務seedを顧客4→14件、荷物4→34件、配送イベント5→65件、問い合わせ2→12件へ増やし、文書は4→10本になった。追加顧客はそれぞれ3荷物を持つ。強風、住所不備、搬送ベルト点検による遅延と、原因・現場が異なる所在不明2件を用意した。旧seedの全レコードが変更されていないこと、ID重複と参照関係を確認した。

## 検証と調整

- 空の独立DBでinit・seed・決定論的な索引準備・自動テストを実行し、初回172件中172件成功。マイグレーション差分なし。
- 初回の実LLM検証では、所在不明・遅延の一覧検索は成功したが、特定顧客の該当なしを`insufficient_evidence`として返す例があった。状態別一覧の0件は正常な否定回答として受理できるよう、Agentと指示を補正した。個別の不存在IDと区別する。
- 最終の全自動テストは177件中177件成功。引数異常、状態の絞り込み・複合条件・上限、検索結果のIDを用いた追加調査、0件の否定回答、seed再投入、マイグレーションの往復とダウングレード拒否、根拠ID・正本の不足を修正する限定的な再試行と予算上限を含む。
- Ruff成功。Alembic差分なし。新しいマイグレーションテストで出た設定の非推奨警告は、`path_separator = os`を明示して解消した。
- 実E5で22正本から26チャンクを再生成。既存RAG確認は4件中4件成功。
- Ollamaの`logiscope-qwen30-probe`（Qwen3 30B-A3B Instruct、8192コンテキスト）で既存A〜Eは5件中5件成功。根拠ID修正のフィードバック追加後も5件中5件成功し、最終結果は`artifacts/demo-status-search-final.json`へ保存した。
- 追加の状態別検索確認は4件中4件成功。所在不明2件、遅延4件、顧客指定の該当なし、条件不足の個別照会をそれぞれ確認した。所在不明の一覧では荷物ID・顧客名の追加指定を求めず、該当なしでは未解決事項を返さない。

追加の個別調査2件は、初回の判定では2件中0件成功だった。強風のケースは原因を検索できても、取得済みsource.idと検索結果のorigin_id/source_keyを混同し、未取得の問い合わせ正本を引用しようとして回答を拒否された。単なる正本引用不足への再試行だけでは改善せず、取得済み根拠IDも明示するフィードバックへ補正した。根拠IDの照合は緩めず、通常のLLM・Tool回数と時間予算の中で修正機会を一度だけ与える。

最終の追加個別調査は2件中2件成功。強風のケースは不足する正本を取得して回答でき、所在不明のケースも現物未確認・調査中・再開時刻未確定という正本の事実に合っていた。公開応答は`artifacts/extra-investigation-verification.json`へ保存した。

一方、所在不明の個別調査は初回から問い合わせ正本に基づく正しい回答だった。報告文書の引用だけを必須にした追加検証の条件が厳しすぎたため、対応する問い合わせ正本も根拠として認めるように変更した。変更前後の公開応答はGit対象外の`artifacts/extra-investigation-initial.json`と`artifacts/extra-investigation-before-source-feedback.json`に残した。

実行は既存WSL・RTX 3060 12GBのローカル環境。公開APIの応答と所要時間はGit対象外の`artifacts/demo-status-search-verification.json`、`artifacts/status-search-verification.json`、`artifacts/rag-verification.json`へ保存し、モデル内部推論は保存していない。ここでの成功は任意の質問の品質保証ではない。

利用者の方針に従い、LICENSEは追加せず、既存v0.2.0のタグ・Releaseを維持する。新しいReleaseやreleaseブランチは作成しない。

## ブラウザ確認後の補正

利用者の質問「今現在、行方不明になっている荷物はある？」では、モデルが単に「現在」と回答した。状態別検索の成功応答に、実行側で「現在の登録データに基づく回答です。」を付けるよう補正した。単体テストでもモデルが「現在」と返すケースと0件の回答で明示を確認した。補正後も自動テスト177件中177件成功、Ruff成功。利用者と同じ質問の実API応答でも冒頭の明示を確認し、公開応答を`artifacts/registered-state-answer.json`へ保存した。

DBeaverへの接続拒否は、通常のCompose構成でDBが再作成され、閲覧用overrideの15432公開が外れたため。既存ボリュームを維持して`docker-compose.db-tools.yml`を適用し、ポート公開を復旧した。同じ原因で再び公開設定が外れないよう、Git対象外のローカル`.env`に`COMPOSE_FILE`を設定し、通常のComposeコマンドでも閲覧用overrideを維持する。WSL側のlocalhost:15432へのTCP接続を確認した。
